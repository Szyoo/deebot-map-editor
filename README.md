# deebot-map-editor

[English](README.en.md) · 中文

科沃斯（ECOVACS）扫地机的地图查看和编辑工具。在本地网页里改房间墙体、切割和合并房间、改名，然后一键上传到机器人。上传会按固件的实际规则自动排好顺序，并拆成小步，每一步都回读核对。

在 DEEBOT T80S PRO 上下水版（class `sd3tgp`，国行云）上实测。其它使用 V2 地图协议（`getMapInfo_V2` / `setMapSet_V2`）的机型理论上也能用，但没有验证过。

> ⚠️ 写地图有风险。上传前会自动备份，但组 1（房间墙）不在备份恢复的范围内。建议先用演示模式熟悉流程，再到真机上从小改动开始。

## 功能

- **查看**：房间墙（组 1）、激光清扫边界（组 6）、美化轮廓（组 2）、建图原始轮廓（type 7）、虚拟墙、地毯、门槛条、巡逻点、栅格残片，可按图层开关。
- **编辑**：
  - 拖动角点和墙，新建墙，双击加角点；
  - 切换墙类型（外墙 / 内墙 / 门段），快速插门；
  - 拆开重叠的角点，自动合并共线点；
  - 切割、合并房间，改名和房间类型；
  - 历史记录、存档点，两侧一致性检查；
  - 图上标注每段墙的长度（mm）和墙角角度，可分别开关：
    - 多个房间共用的墙只画一次、只标一次长度；两侧墙类型不一致时画成双色线；
    - 直角只画直角符号，其它角度才写数字；
    - 共用的角点画成实心点，悬停可看到属于哪些房间；
    - 选中房间时标出它每面墙的全长，并用刻度标出邻居房间在这面墙上的分段点；
  - 选中房间后拖它的墙和角点，默认只改这个房间、不带动相邻房间（有开关可改为联动，按住 ⌥ 可临时反过来）。
- **背景图**：载入户型图等图片垫在地图下面，对照着调墙：
  - 可调透明度、旋转、比例、位置，可左右/上下镜像；
  - 「两点对齐」：在图上点两个参考点，再在地图上点对应位置，一次对齐比例、角度和位置；
  - 「两点定比例」：点一段已知长度的两端，输入实际长度；
  - 图片只保存在本机浏览器里，不会发给机器人或任何服务器。
- **预演（dry-run）**：列出上传将要发送的完整命令序列，并做校验：
  - 切线端点会自动吸附到清扫边界，并检查是否和边界共线；
  - 按房间位置对应设计和机器人上的房间；
  - 写墙会拆成若干步。
- **一键上传**：顺序为备份 → 切割/合并 → 改名 → 逐间分步写墙。每一步写完都回读核对。设备掉线会提示重启，之后从断点继续。
- **演示模式**：用虚构地图和模拟设备跑完整流程，不连机器人。

## 安装

需要 Python 3.14 及以上（依赖的 deebot-client 18 要求 3.14）。

```bash
git clone https://github.com/Szyoo/deebot-map-editor.git
cd deebot-map-editor
python3 -m venv .venv
.venv/bin/pip install -e .
```

依赖 [deebot-client](https://github.com/DeebotUniverse/client.py)，用来登录科沃斯云并发送命令。如果你的型号不在它的支持列表里，本工具会借用一个相近型号的描述来建立连接。本工具只发送原始命令，不受影响。

## 凭据

凭据只从环境变量读取：

| 变量 | 说明 |
|---|---|
| `ECOVACS_USERNAME` | 科沃斯账号 |
| `ECOVACS_PASSWORD` | 密码 |
| `ECOVACS_COUNTRY` | 国家/地区代码，国行填 `CN` |
| `DEEBOT_DID` / `DEEBOT_CLASS` | 可选。账号下有多台设备时，用来指定是哪一台 |

也可以把这些变量写进项目外的文件（每行一条 `KEY=VALUE`）：

- 默认读取 `~/.config/deebot-map-editor/credentials.env`；
- 也可以用 `--env-file 路径` 指定。

**不要把凭据文件放进仓库。** 程序不会打印凭据，也不会把凭据写进任何文件。

## 运行

```bash
# 演示模式：虚构地图 + 模拟设备，随便改、随便传
.venv/bin/deebot-map serve --demo

# 真机：启动后在页面上点「从机器人读取」（只读）
.venv/bin/deebot-map serve
```

浏览器会自动打开 http://127.0.0.1:8790/ 。服务只监听本机，也只接受发往 `127.0.0.1` / `localhost` 的请求。

页面右侧的「上传到机器人」区域有三个按钮：

1. **预演上传（dry-run）**：列出将要发送的全部命令，不发送任何东西。有错误时不能上传。
2. **开始上传**：在预演对话框里点击，确认后开始执行，过程和日志实时显示。
3. **继续**：机器人掉线后，物理重启机器人，然后点「机器人已重启，继续」。程序会先等机器人上线，再从断点接着做。

### 背景图

在左侧「背景图（户型图）」里选择一张图片，它会先按比例铺满地图范围。然后：

1. 点「两点对齐」，在户型图上依次点两个容易辨认的点（比如两个外墙角），再在地图上点它们对应的位置（靠近墙角会自动吸附）。
2. 需要微调时，勾选「调整背景图」：拖动平移，⌥+滚轮缩放，⇧+滚轮旋转；也可以直接输入数值。调整期间地图本身不能编辑，取消勾选即可恢复。
3. 打开「墙长（mm）」和「墙角角度」图层，就能对照户型图上的尺寸拖墙。

背景图和摆放参数按地图分别保存在浏览器里，下次打开会自动恢复。

### 命令行

```bash
deebot-map fetch                         # 读取地图，保存快照（只读）
deebot-map plan  design.json             # dry-run：列出命令序列
deebot-map upload design.json            # 同样只是 dry-run
deebot-map upload design.json --yes      # 真正上传（终端里还要输入 yes 确认）
deebot-map upload design.json --demo --yes   # 对模拟设备执行
deebot-map wait-online                   # 等机器人重新上线
```

`design.json` 由页面上的「导出设计文件」按钮生成。仓库里的 `examples/demo-design.json` 是对演示地图的一份设计（切开客厅、外推一面墙、改名），可以直接试：

```bash
deebot-map plan examples/demo-design.json --demo
deebot-map upload examples/demo-design.json --demo --yes
```

快照和断点日志默认放在 `~/.local/share/deebot-map-editor/`，可以用 `--data-dir` 或环境变量 `DEEBOT_MAP_DATA` 修改。

## 工作原理

### 地图数据

| 数据 | 读取命令 | 说明 |
|---|---|---|
| 房间列表 | `getMapSet_V2 {type:"ar"}` | mssid、名字、类型、中心点等 |
| 组 1：房间墙 | `getMapInfo_V2 {type:"0"}` | 每个房间一段 `序号;x,y,T;x,y,T;…`。**开头是顺序序号，不是 mssid** |
| 组 2：美化轮廓 | 同上 | 以 mssid 开头 |
| 组 6：清扫边界 | 同上 | 以 mssid 开头。由激光数据生成，决定房间之间实际怎么划分 |
| type 7：原始轮廓 | `getMapInfo_V2 {type:"7"}` | 建图时的房间轮廓 |

几点约定：

- 坐标单位是 mm，y 轴向上为负。
- 墙点里的 `T` 表示「以这个点结尾的那段墙」的类型：`1` 外墙，`2` 内墙，其它值（如 `3-1-0`）是门类段。
- `info` / `subsets` 字段是 base64 编码的 zstd 或 LZMA 压缩 JSON。
- 组 1 的序号按房间列表的顺序对应 mssid。mssid 不连续时（比如 0、1、2、4、5，演示地图就是这样）必须换算，本工具在读取和写入时都会自动处理。

### 上传顺序

1. **备份**：发送 `setCachedMapInfo {act:"backup"}`。
2. **切割 / 合并**：发送 `setMapSet_V2`，`act` 为 `divide` 或 `merge`。
   - 这两个操作会让固件重新生成全图的组 1，并清空相关房间的名字，所以必须最先做完。
   - divide 的两个端点必须落在被切房间的组 6 边界上，容差约 10 cm。端点离边界稍远时，本工具会自动吸附；离得更远时，会沿切线方向找边界。
   - 切线和组 6 的某条边重合会失败（返回 20004）。切线和边平行但相距一格（25 mm）可以成功。
   - `value` 用设备坐标，y 不取反。
   - 每做完一个操作，都重新读取地图，用房间数确认它已生效。
3. **改名**：先按几何位置，把设计里的房间对应到机器人上的 mssid。做法是在设计房间内取样，看样点落进哪个房间的组 6。然后逐个发送 `rename`。
   - 切开后固件把新编号分给哪一半是不确定的，所以只能按位置对应。
4. **写墙**：发送 `setMapInfo_V2 {type:"1", info:["1", 每个房间一段…]}`。
   - `info` 必须是一维数组。发送二维数组会清空组 1。
   - 一次改动太大，设备会不回包、掉线，并丢弃这次写入。所以本工具每次只改一个房间，大的改动再拆成几步：
     1. 先把新角点插在原来的墙上（几何不变）；
     2. 再分几步移动角点，每步单点移动不超过「每步最大移动」（默认 300 mm）；
     3. 然后改墙段类型；
     4. 最后删掉多余的角点（这时它们已经在目标墙线上）。
   - 每步写完等约 6 秒，再回读组 1。和写入内容完全一致，才继续下一步。

### 掉线与续传

每完成一步，都会记进断点日志。遇到下面两种情况会停下来：

- **设备不回包**：提示物理重启机器人。重启上线后，用同一个设计文件继续，会从断点接着做。
  - 如果停在切割上，会先用房间数判断上次的切割有没有生效：生效了就跳过，没生效就重发。
  - 改名和写墙每次都按机器人当前的状态重新计算，已经完成的步骤不会重复发送。
- **回读不一致**：说明固件没有接受这一步。可以把「每步最大移动」调小，再重新上传。

### 编辑规则

App 对拖墙有不少限制，比如只能外推、墙长至少 0.5 m、内墙和门段不能动、角点数不能变。实测固件并不强制这些规则，所以编辑器不再为它们报警。

编辑器仍会提示可能真正有问题的情况：

- 墙线自相交；
- 墙长度为 0；
- 房间重叠；
- 两侧墙类型不一致。

### 其它命令

虚拟墙、地毯、门槛条、材质、巡逻点、家具等编辑的命令格式来自 App 逆向，还没有在真机上实测。这些命令默认不发送；勾选「未实测命令：一起发送」后，会放在改名之后、写墙之前发送。

## 开发

```bash
.venv/bin/pip install -e '.[dev]'
.venv/bin/python -m pytest
.venv/bin/ruff check .
python examples/make_demo.py      # 重新生成演示地图
```

每次推送和 PR 会在 GitHub Actions 上跑 ruff 和测试。

代码结构：

| 文件 | 内容 |
|---|---|
| `src/deebot_map_editor/mapdata.py` | 解码、快照格式、组 1 序号与 mssid 的映射、编辑器数据 |
| `src/deebot_map_editor/plan.py` | 上传规划（纯函数）：切线校验、房间对应、写墙拆步 |
| `src/deebot_map_editor/upload.py` | 执行器：断点日志、回读核对、掉线处理 |
| `src/deebot_map_editor/cloud.py` | 科沃斯云会话 |
| `src/deebot_map_editor/fake.py` | 模拟设备（演示和测试用） |
| `src/deebot_map_editor/server.py` | 本地网页服务 |
| `src/deebot_map_editor/web/editor.html` | 单页编辑器 |
